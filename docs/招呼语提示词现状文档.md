# Boss海投助手 - 招呼语生成现状文档

> 用途：把插件当前招呼语生成的全部代码、提示词、配置、调研结论整理出来，便于复盘和优化。

---

## 一、功能位置

招呼语生成逻辑在插件 Service Worker 中：

- 文件：`boss-helper1.1.1/boss-extension/src/background.js`
- 函数：`generateGreeting(cfg, job, jd)`
- 调用位置：`runDeliver()` 流程中，每个岗位打开页面读 JD 之后、点击"立即沟通"之前

生成结果会缓存 24 小时（避免同岗位重复扣费）。

## 二、三档策略定义（STRATEGY_NOTES）

```js
const STRATEGY_NOTES = {
  aggressive: '突出成就：强调可验证的量化成果（如提升40%、覆盖50万用户），姿态自信主动，明确表达期待进一步沟通。',
  balanced: '经验陈述：客观说明与岗位强相关的经验或项目，匹配JD关键词，保持诚恳踏实。',
  conservative: '背景对齐：简洁陈述背景与岗位方向的匹配，不夸大不讨好，姿态平等克制。'
};
```

UI 上的卡片副标题：
- 激进 — 突出成就
- 均衡 — 经验陈述
- 保守 — 背景对齐

用户在侧边栏 ③ 投递设置 → 对话策略 中单选一档，默认均衡。

## 三、generateGreeting 完整代码

```js
// ── 招呼语生成（带缓存）──
async function generateGreeting(cfg, job, jd) {
  const cacheKey = greetingCacheKey(job);
  const cached = await getCachedGreeting(cacheKey);
  if (cached && cached.trim()) {
    log('  [缓存] 命中历史招呼语: ' + cached.trim().slice(0, 30) + '...');
    return cached;
  }

  const resumeText = (cfg.resumeText || '').trim();
  const resumeAnalysis = (cfg.resumeAnalysis || '').trim();
  const smartPrompt = (cfg.smartGreetingPrompt || '').trim();
  const strategy = STRATEGY_NOTES[cfg.conversationStrategy] || STRATEGY_NOTES.balanced;
  const sys = '你是求职者本人，在BOSS直聘给HR发首条招呼语。回复会原样发给HR。\n' +
    '【硬性规则】\n' +
    '1.全文40-70字，中文，像一个真人在打字\n' +
    '2.开头必须使用岗位锚定式：首句明确指出应聘的岗位全称，例如"您好，对贵司【岗位名称】很感兴趣"\n' +
    '3.绝对不能向HR提问，不能用问号，不能索要面试机会，不能用"方便聊聊吗"等索取式表达\n' +
    '4.不能用emoji、感叹号、括号备注、字数统计、引导语\n' +
    '5.不要卑微讨好的语气，保持平等专业的姿态\n' +
    '6.策略侧重：' + strategy + '\n' +
    '7.第二句必须给出一句与该岗位强相关的可验证经验或项目，优先使用简历中真实存在的数字成果\n' +
    '8.第三句呼应JD中明确要求的关键词或职责，说明与简历的匹配点\n' +
    '9.结尾以句号结束，保持专业节制感';
  const jdText = (jd && jd.trim()) ? jd.trim().slice(0, 2000) : ((job.tags || []).join('、'));
  const companyInfo = job.company ? ('（' + job.company + '）') : '';
  const salaryInfo = job.salary ? (' | 薪资：' + job.salary) : '';
  // 交叉引用：简历分析 + 自定义提示词
  let extraBlocks = '';
  if (resumeAnalysis) extraBlocks += '\n\n【简历AI分析（核心技能/经验亮点/优势）】\n' + resumeAnalysis.slice(0, 600);
  if (smartPrompt) extraBlocks += '\n\n【用户额外要求】\n' + smartPrompt;

  const user = '【我的简历】\n' + (resumeText || '无') + extraBlocks +
    '\n\n【目标岗位】' + (job.name || '') + companyInfo + salaryInfo +
    '\n\n【该岗位JD】\n' + jdText +
    '\n\n请直接输出招呼语本身，不要任何多余内容。';
  try {
    let greeting = await callAISmart(cfg, [{ role: 'system', content: sys }, { role: 'user', content: user }], 2000);
    greeting = (greeting || '').trim();
    if (greeting) await setCachedGreeting(cacheKey, greeting);
    return greeting;
  } catch (e) {
    log('  招呼语生成异常: ' + e.message, 'error');
    return '';
  }
}
```

## 六、相关配置项

| Storage Key | 类型 | 说明 |
|---|---|---|
| `conversationStrategy` | string | `aggressive` / `balanced`(默认) / `conservative` |
| `smartGreetingPrompt` | string | 用户自定义额外提示词，会拼到 user prompt 里 |
| `resumeText` | string | 简历全文，招呼语生成的主要素材 |
| `resumeAnalysis` | string | AI 分析简历得到的核心技能/亮点，作为补充素材 |

UI 入口：`sidepanel.html` → ③ 投递设置：
- "招呼语自定义提示词" textarea（`id="smartGreetingPrompt"`）
- "对话策略" 三档单选卡片

## 七、AI 调用链路

```
generateGreeting()
  └─ callAISmart()  // 本地包装
       └─ callAI()
            └─ fetch POST {API_BASE}/api/chat
                 body: { client_id, messages, max_tokens: 2000, temperature: 0.5 }
```

- `API_BASE = 'https://boss.luckyioo.cc.cd'`（Cloudflare Worker 反代，国内可访问）
- Worker 后端转发到 DeepSeek API（默认模型 `deepseek-v4-flash`）
- 投递成功后会扣 1 点额度；AI 请求本身不扣费（仅校验余额）
- 招呼语缓存 24 小时（键：`greet_{岗位ID}`），命中缓存不调用 AI

## 八、岗位锚定式开头的设计依据（调研结论）

来自 BOSS 直聘招呼语最佳实践调研：

1. **岗位锚定**——首句明确指出应聘的岗位全称（不是简单"您好"开场）
   - HR 3 秒内判断相关性，复述岗位名建立专业匹配印象
   - 例："您好，对贵司【Java开发工程师-电商方向】很感兴趣"

2. **经验直给**——前置一句可验证经验，带数字最好
   - 用"提升40%""覆盖50万用户"等量化表达替代"熟悉""较好"
   - 例："具备3年Spring Cloud微服务开发经验，主导过订单履约模块重构"

3. **JD 关键词呼应**——明确说"与 JD 中 XX 要求匹配"
   - 让 HR 感知求职者真读过 JD，不是群发

4. **不提问、不索要面试、不加表情**——专业节制感
   - 结尾不加问号、不加"方便聊聊吗"，以句号结束

5. **不要"卑微讨好感"**——保持平等姿态
   - 避免"希望贵公司给我一次机会"这类自降身价的表述

调研来源：
- https://m.php.cn/faq/2178416.html
- https://m.guofenba.com/rjjc/421520.html

## 九、用户明确的要求

1. 字数范围 **40-70 字**（之前是 80-120 字，BOSS 首条展示容易截断）
2. **绝对不向 HR 提问**（不能用问号、不能索要面试）
3. 三档策略按 **内容侧重** 区分（不是只改语气）
4. 开头使用 **岗位锚定式**

## 十、当前实现尚不确定的点（建议讨论）

1. **第二句"可验证经验"**——若简历里没有数字成果，AI 可能会编造。是否需要加规则"若无真实数字，则用定性描述，禁止编造"？

2. **第三句"JD 关键词呼应"**——目前没限定一定要从 JD 提取哪个关键词，AI 可能抓不准。是否需要预先从 JD 抽 3-5 个核心关键词再喂给 AI？

3. **岗位全称来源**——`job.name` 来自搜索页卡片解析，可能被截断或简写。是否需要从 JD 页面重新提取完整岗位名？

4. **三档策略是否足够区分**——目前只改了内容侧重描述，AI 生成时可能仍输出相似结果。是否需要为每档策略单独写一个 prompt 模板，而不是共用一个 sys + 替换描述？

5. **缓存键**——目前用 `job.id`（搜索页 job_detail 路径），同一岗位跨城市可能 ID 不同，导致重复生成。是否需要用"公司+岗位名"做缓存键？
